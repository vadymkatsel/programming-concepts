# Технічний огляд проєкту "Programming Concepts Course"

Цей документ містить технічний аналіз кодової бази проєкту, включаючи конфігурацію, пайплайни, скрипти та архітектурні рішення, на які варто звернути увагу при створенні нових фіч.

## 1. Архітектура та стек технологій

Проєкт є статичним вебсайтом-книгою (course website), згенерованим за допомогою фреймворку **Quarto**. 
- **Генератор:** Quarto (вихідна тека `docs/`).
- **Стилізація:** Vanilla CSS (кастомні змінні, сучасні ефекти на кшталт glassmorphism).
- **Інтерактивність:** Vanilla JavaScript.
- **Хостинг:** GitHub Pages.
- **Залежності для контенту:** Python 3.10 (Jupyter, Pandas, Matplotlib, Numpy, Great-Tables).

## 2. Конфігурація Quarto (`_quarto.yml`)

Головний файл конфігурації `_quarto.yml` містить важливі налаштування:
- **Структура курсів:** Курси (Math, BE, EBD) логічно розділені за допомогою різних `sidebar` конфігурацій з власними ідентифікаторами (`math-sidebar`, `be-sidebar`, `ebd-sidebar`) та параметром `active-modes`. Це дозволяє динамічно перемикати сайдбари залежно від відкритого курсу.
- **Оформлення:** Використовується базова тема `cosmo` для світлого режиму та `darkly` для темного, але вона значно перевизначається через підключення власного файлу `style.css`.
- **Заморожування виконання (`freeze: auto`):** Обчислення коду у `.qmd` файлах кешуються. Це означає, що код у лекціях не буде виконуватись заново при кожній збірці сайту, якщо сам файл не змінювався.
- **Ресурси:** Усі додаткові скрипти та стилі (`style.css`, `index.css`, `script.js`, теки `sources/`) явно вказані у блоці `resources`. 

## 3. CI/CD Пайплайни (GitHub Actions)

В теці `.github/workflows/` налаштовано два ключових пайплайни:
1. **`pr-check.yml`**: Спрацьовує на Pull Requests до гілки `main`. Встановлює Quarto, Python та необхідні пакети через `pip install` (зверніть увагу: залежності захардкоджені в пайплайні, а не в `requirements.txt`). Виконує тестовий `quarto render`, щоб перевірити, чи збирається сайт без помилок, але не публікує його.
2. **`publish.yml`**: Спрацьовує при пуші в гілку `main` або ручному запуску. Збирає сайт і розгортає артефакт в середовище `github-pages`. Використовується механізм токенів доступу та конкурентності (`concurrency: cancel-in-progress: true`), що зупиняє старі збірки, якщо прийшов новий пуш.

## 4. Фронтенд: Стилі та Скрипти (UI/UX)

Відповідно до персони **Web Architect**, проєкт робить значний акцент на сучасний UI/UX.

### Стилізація (`style.css`)
- **Змінні (CSS Tokens):** Повна підтримка темного/світлого режимів реалізована через кастомні змінні CSS, прив'язані до селектора `body.quarto-dark`.
- **Glassmorphism:** Широко використовується `backdrop-filter: blur(12px)` разом із напівпрозорими кольорами для таблиць, панелей вкладок (`panel-tabset`), навігації та сайдбарів. Це створює "преміальний" ефект.
- **Адаптивність (Responsive Design):** Є жорсткі медіа-запити для різних розширень:
  - `≤ 991px`: Приховання правого сайдбару, зміна позиціонування лівого сайдбару на плаваюче (dropdown), перенесення хедера.
  - `≤ 700px`: Додаткові оптимізації відступів.

### Інтерактивність (`script.js`)
Тут криється **важливий технічний нюанс**. Через те, що стандартна сітка Quarto (grid) не завжди гнучко підтримує кастомні "скляні" панелі на всю ширину, `script.js` використовується для динамічного синхронізування ширин компонентів (футера, навігації, сайдбарів) відносно ширини основного контенту (`main.content`).
- Слухаються події `resize` та `scroll`.
- На льоту вираховуються розміри через `getBoundingClientRect()` і задаються через inline-стилі або CSS-змінні (наприклад, `--pill-width`, `--pill-left`).

> [!WARNING]
> Будь-які зміни в HTML-структурі або додавання нових блокових елементів, що виходять за межі `main.content`, можуть поламати логіку синхронізації розмірів у `script.js`. Змінюючи сітку або навігацію, обов'язково перевіряйте поведінку при ресайзі вікна браузера.

## 5. Технічні нюанси, на які варто звернути увагу

1. **Відсутність `requirements.txt`:** Залежності Python (`jupyter`, `pandas`, `matplotlib`, `numpy`, `great-tables`) встановлюються прямо у файлах `.yml`. Якщо нова фіча потребуватиме нових бібліотек, обов'язково треба оновити обидва GitHub Actions файли.
2. **Динамічний розрахунок розмірів у JS:** Як зазначено вище, `script.js` жорстко прив'язаний до класів `#quarto-sidebar`, `#quarto-margin-sidebar` та `main.content`. Додаючи нові елементи, намагайтесь вбудовувати їх всередину цих існуючих контейнерів.
3. **Обмеження Quarto Markdown:** Проєкт використовує спеціалізовані блоки Quarto (наприклад, `.panel-tabset`, кастомні секції `active-modes`). При розробці нових фіч слід максимально використовувати можливості самого Quarto, перш ніж писати кастомні HTML-вставки, та стилізувати їх через Vanilla CSS відповідно до наявного дизайн-коду.
4. **Персона Web Architect:** При розробці UI суворо заборонено використання важких фреймворків (наприклад, Tailwind, Bootstrap тощо, крім того, що генерує сам Quarto). Тільки Vanilla CSS/SCSS і чистий JS.
